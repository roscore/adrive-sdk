# ADrive 리니어 액추에이터 퀵스타트 (SDK 0.1)

## 1. 준비물

| 항목 | 내용 |
|---|---|
| PC | Windows 10/11 64-bit, Python 3.10 이상 (3.10–3.13 에서 같은 wheel 하나를 씁니다) |
| 액추에이터 | ADrive-LH42 + 48 V 직류 전원 |
| 연결 | USB 케이블(기본) 또는 CAN 어댑터 — 4장 참고 |
| 안전 | **전원 차단형 비상정지 스위치**(필수). SDK 의 `estop()` 은 소프트웨어 정지이고 안전 등급이 아닙니다 |
| 고정 | 액추에이터 본체를 바이스·클램프·볼트로 고정하십시오. 양면테이프 고정은 금지(가속 시 이탈) |
| 펌웨어 | 펌웨어 빌드 06 이상에서 SDK 연결을 확인했습니다. 06 이전의 기존 출하 펌웨어도 동작합니다. 06 직전의 일부 시험 빌드는 연결되지 않습니다(9장 `E111` 참조) |

## 2. 설치

```
pip install adrive-0.1.1-cp310-abi3-win_amd64.whl
python -c "import adrive; print(adrive.build_info())"
```

- **드라이버 설치가 필요 없습니다.** 액추에이터는 MS OS 디스크립터(호환 ID `WINUSB`)를 제공해서 Windows 8.1 이후에서 WinUSB 로 자동 인식됩니다(Zadig 불필요).
- 장치 관리자에서 COM 포트가 하나 같이 보일 수 있습니다. SDK 는 그 포트를 쓰지 않습니다.
- `build_info()` 의 `build_sha` 는 지원 문의 때 알려 주십시오.

## 3. 처음 연결 — 호밍은 반드시 먼저

전원을 켜기 전에 캐리지를 스트로크 중앙 부근, 양 끝에서 떨어진 위치에 두십시오. 전원을 켜면 액추에이터가 스스로 짧게 움직이며 엔코더 인덱스를 찾고 엔코더를 맞춥니다(정상. 8장 7번 참조). 그 뒤 **호밍(원점 찾기)을 한 번 해야 이동 명령이 허용됩니다.** 호밍은 수축 방향 끝의 엔드스톱 스위치까지 2 mm/s 로 천천히 움직이고, 그 점을 0 mm 로 잡습니다.

```python
import adrive

print(adrive.scan())                 # ['usb:<serial>']  — 연결된 액추에이터 목록
with adrive.connect() as act:        # 1대면 자동 선택. 여러 대면 connect("usb:<시리얼>")
    print(act.info())                # 모델, 시리얼, 펌웨어
    act.home()                       # 전원 투입 후 1회 필수 (최대 60 s)
    act.enable()                     # 현재 위치를 유지하며 제어 시작
    act.move_to(10.0)                # 10 mm 로 이동 (기본 20 mm/s, 100 mm/s²)
    print(act.position())            # mm
    act.move_to(3.0, speed=50, accel=500)
# with 블록을 나가면 모터는 자동으로 꺼집니다(disable)
```

- 단위는 항상 **mm, mm/s, mm/s², N, s** 입니다.
- 이동 범위(소프트 리밋)는 기본 0.5–65 mm 입니다. `act.set_soft_limits(2, 20)` 처럼 좁힐 수만 있고 넓힐 수는 없습니다.
- 속도·가속 상한은 200 mm/s, 2000 mm/s² 입니다. 생략하면 그 10 % 를 씁니다.
- `move_to(..., wait=True)`(기본)은 목표 ±10 µm 에 들어가거나, 궤적이 끝나고 0.5 s 동안 멈춰 있으면 반환합니다. 마찰 때문에 수 µm–수십 µm 가 남을 수 있으니 `position()` 으로 확인하십시오.

## 4. USB / CAN 자동 인식

> **CAN 으로는 아직 움직일 수 없습니다 (현 펌웨어).** 현 펌웨어는 CAN 호밍을 지원하지 않아 SDK 가 거부합니다. SDK 는 호밍하지 않은 축의 이동도 거부합니다. 따라서 CAN 축은 찾기·상태 보기·정지만 됩니다. 이후 펌웨어에서 CAN 이동이 지원될 때까지 **이동은 USB 로 하십시오.** 실제 CAN 어댑터는 이 배포에서 하드웨어로 시험하지 않았습니다(미검증).

| 연결 | 방법 | 상태 |
|---|---|---|
| USB | `adrive.connect()` / `connect("usb:<시리얼>")` — 자동 인식 | 지원 |
| CAN | 자동 인식(하트비트) 또는 `connect("can:<백엔드>:<채널>:<노드ID>")` | 찾기·상태·정지만. 이동 불가(위 참고). 실 어댑터 미검증 |

**지원 CAN 어댑터**

| 어댑터 | 백엔드 | 타깃 예 | 주의 |
|---|---|---|---|
| PEAK PCAN-USB | `pcan` | `can:pcan:usb1:16` | PEAK 의 PCAN-Basic 드라이버(DLL)를 먼저 설치하십시오 |
| candleLight / gs_usb (예: candleLight 펌웨어의 CANable) | `gsusb` | `can:gsusb:0:16` | WinUSB 드라이버가 필요합니다 |
| slcan (CANable 기본 펌웨어) | `slcan` | `can:slcan:COM5:16` | COM 포트로 보입니다 |
| Linux SocketCAN | `socketcan` | `can:socketcan:can0:16` | 인터페이스는 미리 1 Mbit/s 로 올려 두십시오 |

- 비트레이트는 **1 Mbit/s** 입니다.
- 자동 인식은 드라이브 하트비트를 약 1.6 s 동안 듣고 축을 찾습니다. 축은 CAN 노드 ID 로 구분합니다(기본 16 = 0x10).
- CAN 으로는 시리얼 번호와 펌웨어 버전을 알 수 없습니다. 노드 ID 만 보입니다.
- 같은 버스에 노드 ID 가 겹치면 그 ID 는 경고를 내고 자동 인식에서 뺍니다(`can:...` 로 직접 지정하면 연결은 됩니다). 여러 대를 한 버스에 둘 때는 노드 ID 를 모두 다르게 하십시오.
- CAN 탐색을 건너뛰려면 환경 변수 `ADRIVE_CAN_SCAN=0` 을 설정하십시오.
- 여러 대: `adrive.connect_all()` 은 USB 로 연결된 모든 액추에이터와 자동 인식으로 찾은 CAN 축을 엽니다(`ADRIVE_CAN_SCAN=0` 이면 CAN 제외). 찾지 못한 CAN 노드는 `connect_all(["can:pcan:usb1:16", "can:pcan:usb1:17"])` 처럼 직접 추가하십시오.

## 5. 힘 제어

```python
act.force_control(10.0, max_speed=2.0)      # +10 N 으로 밉니다, 속도는 2 mm/s 이하
```

- **명령 유효기간(lease)**: 힘 명령은 기본 1 s 동안만 유효합니다. 계속 밀려면 그 안에 `force_control` 을 다시 불러야 합니다. 스크립트가 멈추거나 오류로 빠지면 액추에이터는 그 자리에서 위치를 유지합니다.

```python
end = time.time() + 5
while time.time() < end:
    act.force_control(10.0, max_speed=2.0, lease=0.5)
    print(act.force())                       # N (추정치)
    time.sleep(0.1)
act.stop()                                   # 현재 위치 유지
```

- `force()` 는 모터 전류로 계산한 **추정치**입니다. 스크루 마찰이 보정되지 않아 수십 N 오차가 날 수 있습니다. 정밀한 힘(±1 N)은 로드셀이 필요합니다. 힘 정밀도는 아직 로드셀로 검증하지 않았습니다.
- 힘 모드에서 소프트 리밋을 넘으면 그 위치에서 멈추고 위치 유지로 바뀝니다. 아무것도 밀지 않는 상태(무부하)에서 힘을 주면 속도 상한까지 움직인 뒤 리밋에서 멈춥니다.

## 5-1. 스트로크 한계

```python
act.set_stroke_limits(2.0, 20.0)              # 호밍 원점 기준 mm, 0 <= 최소 < 최대 <= 65
act.set_stroke_limits(2.0, 20.0, save=True)   # 이 PC 에 이 유닛 값으로 기억, 다음 연결부터 자동 적용
print(act.get_stroke_limits())
```

- 범위 밖 `move_to` 는 **거부**됩니다(`SafetyError`, 움직이지 않음). 범위 안으로 잘라 이동하지 않습니다.
- 힘 모드에서 한계를 넘으면 그 위치에서 위치 유지로 바뀝니다.
- 드라이브에는 위치 한계 설정이 없어 SDK 가 강제합니다. `save=True` 는 드라이브가 아니라 **이 PC** 에 저장됩니다(`%APPDATA%\adrive\stroke-limits.txt`). 다른 PC·다른 프로그램에는 적용되지 않습니다.

## 5-2. 게인 튜닝

```python
print(act.get_gains())        # {'pos': 300.0, 'vel': 0.015, 'vel_integrator': 0.02}
print(act.gain_limits())      # 허용 범위
act.set_gains(vel=0.02)       # RAM 에만 적용, 전원을 끄면 원래 값
act.restore_factory_gains()   # 출하값으로 되돌림 (RAM)
act.disable(); act.save()     # 드라이브에 저장 — 드라이브가 재부팅됩니다
```

- 허용 범위: 출하값의 **0.2–5 배**, 그리고 절대 한계(pos 20–1500, vel 0.0005–0.08, vel_integrator 0.001–0.1) 안. 범위 밖은 거부됩니다.
- 범위 검사는 SDK 가 모든 펌웨어에서 합니다. 펌웨어 빌드 06 이상은 드라이브도 범위 밖 게인 쓰기를 거부합니다. 06 이전 펌웨어에서는 SDK 를 거치지 않은 쓰기를 드라이브가 검사하지 않습니다.
- 출하 게인은 유닛별 성적서 값이라 유닛마다 다릅니다(위 예시는 한 유닛의 값입니다). 바꾼 게인은 `restore_factory_gains()` 로 출하값으로 되돌리십시오.
- 출하값은 연결할 때 드라이브에서 읽은 값입니다. `save()` 로 바꾼 뒤에는 성적서 값을 `act.set_factory_gains(pos, vel, vel_integrator)` 로 지정합니다.
- `save()` 는 모터를 끈(`disable()`) 상태에서만 됩니다. 저장 후 드라이브가 재부팅하며 **시동 시퀀스(엔코더 인덱스 탐색 등)로 축이 움직일 수 있습니다**. 주변을 비우십시오. 이후 다시 `connect()` → `get_gains()` 확인 → 호밍 순서로 진행하십시오.
- 한 번에 크게 바꾸지 마시고 1.5 배 이내로 바꾸며 GUI 의 스텝 응답(오버슈트·정착 시간)을 확인하십시오.

## 6. 4축 동기 제어 예제

```
python examples/sync_4axis.py                      # USB 로 연결된 모든 축
python examples/sync_4axis.py --extra can:pcan:usb1:16   # CAN 노드 추가 (현재는 이동 불가 — 4장)
python examples/sync_4axis.py --sim 3              # 하드웨어 없이 시뮬레이터 축 추가
```

모든 축을 동시에 호밍한 뒤, 축마다 다른 거리를 같은 시간에 이동합니다. 이동마다 시작 동기 오차(명령·실제 출발 시각의 차), 축 간 위상 오차(중간점 통과 시각의 차), 이상 프로파일 대비 최대 편차를 출력합니다. 한 축이라도 에러가 나면 모든 축을 즉시 정지합니다.

현 펌웨어에서는 CAN 축이 하나라도 섞이면 그 축의 호밍이 거부되고, 예제는 모든 축을 정지한 뒤 끝납니다(4장). 지금은 USB 축으로만 이동합니다. CAN 배선·어댑터별 주의는 `examples/sync_4axis.py --help` 에 있습니다.

Windows 용 단일 실행 파일 `ADrive-GUI.exe` 를 제공합니다. 설치 없이 실행합니다. Tk 로 만들었고 공개 SDK 만 씁니다.

| 화면 / 기능 | 내용 |
|---|---|
| 장치 목록 | USB·CAN 자동 인식. 시리얼, 모델, 펌웨어, 링크를 보여 줍니다 |
| 연결 / 해제 | 목록에서 골라 연결합니다 |

- 4장의 CAN 제한은 GUI 에도 똑같이 적용됩니다.
- 한 번에 한 프로그램만 장치를 열 수 있습니다. GUI 를 쓰는 동안 다른 파이썬 스크립트로 같은 장치를 열지 마십시오.
- 소스에서 하드웨어 없이 시뮬레이터 4축으로 실행: `python gui/adrive_gui.py --sim 4`

## 8. 안전 수칙

1. 처음 움직일 때는 낮은 속도(≤ 10 mm/s)와 짧은 거리(1–5 mm)로 방향을 확인하십시오. 양(+) 방향 = 엔드스톱에서 멀어지는 쪽(신장).
2. 사람의 손·몸이 로드 끝 이동 범위 안에 들어가지 않게 하십시오. 전원 차단 비상정지를 손 닿는 곳에 두십시오.
3. **열 보호 주의**: 이 버전은 드라이버 온도 감시가 동작하지 않습니다(측정값 무효). 고속 왕복을 연속으로 오래 돌리지 마시고, 짧게 돌린 뒤 쉬는 시간을 두십시오.
4. 스트로크 끝(0 mm 쪽 엔드스톱, 69 mm 쪽 기구 끝)에 부딪히지 않게 소프트 리밋을 쓰십시오.
5. 프로그램이 죽으면 0.5 s 안에 모터가 꺼집니다(통신 감시). 꺼진 모터는 힘을 내지 않으므로, 수직 설치나 외력이 있는 구조에서는 축이 밀릴 수 있습니다.
6. 펌웨어·설정 변경 도구는 제공하지 않습니다. 분해·개조하지 마십시오.
7. **전원 인가 직후 엔코더 탐색**: 전원을 인가하면 드라이브가 스스로 엔코더 인덱스를 찾고 캘리브레이션하며, 이때 캐리지가 짧게 움직입니다. 전원을 켜기 전에 캐리지를 양 끝에서 15 mm 이상 떨어뜨리고, 엔드스톱·바이스·지그·부하에 걸리지 않게 하십시오. 걸리면 이동량이 모자라 드라이브가 `ENCODER_FAILED`(0x100), 엔코더 오류 `CPR_POLEPAIRS_MISMATCH`(0x2)를 보고하고 모터는 꺼진 채로 남습니다(9장 참조).

## 9. 문제 해결

| 증상 | 원인 / 조치 |
|---|---|
| `NotFoundError` | USB 케이블·전원 확인. `adrive.scan()` 이 빈 목록이면 장치 관리자에서 인식 여부 확인 |
| `LinkError: E102 device busy` | 다른 프로그램(다른 파이썬, GUI)이 이미 장치를 열고 있습니다. 한 번에 한 프로그램만 연결할 수 있습니다 |
| `SafetyError: not homed` | 전원 투입 후 `home()` 을 먼저 실행 |
| `SafetyError: ... outside soft limits` / speed | 목표·속도가 허용 범위 밖. 메시지의 범위 안으로 |
| `FaultError (code ...)` | 액추에이터가 보호 정지했습니다. `disable()` → `clear_faults()` → 원인 확인 후 `enable()`. 코드는 지원 문의에 적어 주십시오 |
| 프로그램이 죽은 뒤 다음 연결에서 `FaultError` | 통신 감시가 모터를 끈 기록입니다. `clear_faults()` 로 지우십시오 |
| `TimeoutError` (move_to) | 목표 근처에서 마찰로 천천히 다가가는 중일 수 있습니다. `timeout=` 을 늘리거나 `wait=False` 후 `position()` 확인 |
| `LinkError ... reconnect required` | 통신이 끊겼습니다. 케이블을 확인한 뒤 `connect()` 를 다시 호출하십시오(자동 재연결은 하지 않습니다 — 의도적) |
| 연결 시 `LinkError: E111` | 드라이브 펌웨어가 SDK 연결을 지원하지 않는 시험 빌드입니다. 지원 문의로 펌웨어 빌드 06 이상 업데이트를 요청하십시오 |
| 전원 인가 직후 엔코더 오류 `CPR_POLEPAIRS_MISMATCH`(0x2) / `ENCODER_FAILED`(0x100), 모터가 꺼진 채 | 전원 인가 직후 엔코더 탐색 구간에서 캐리지가 걸려(엔드스톱에 붙어 있음, 바이스·지그 간섭, 부하 연결) 실제 이동량이 모자란 경우입니다. 전원을 끄고, 캐리지를 손으로 엔드스톱에서 15 mm 이상 떨어뜨리고 걸림을 제거한 뒤 전원을 다시 켜십시오. 재발하면 엔코더 커넥터를 확인하십시오. 저장된 설정값 문제가 아닙니다 |
